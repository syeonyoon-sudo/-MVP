# 냉장고 한 끼

냉장고 속 식재료와 소비기한을 입력하면, **먼저 써야 할 재료**를 날짜 규칙으로 골라내고
**요리 실력·취향·조리시간·조리도구·알레르기**에 맞는 메뉴를 최대 3개 추천해 주는 웹앱(MVP)입니다.

- React + TypeScript + Vite + Tailwind CSS + Lucide 아이콘
- Vercel 서버리스 함수로 AI(Claude API) 연결 — API 키는 브라우저에 노출되지 않음
- API 키가 없으면 자동으로 **데모 모드**(내장 메뉴 37개 + 규칙 기반 추천)로 동작
- 데이터는 브라우저 localStorage에 저장 (회원가입·로그인 없음)

---

## 1. 배포 후 사용 방법

배포가 끝나면 Vercel이 만들어 준 주소(예: `https://fridge-meal.vercel.app`)를 열기만 하면 됩니다.
사용자는 Node.js, npm, 터미널 등 아무것도 설치할 필요가 없습니다.

1. 처음 접속 → 요리 실력·취향·조리 조건 3단계 설정 (건너뛰기 가능)
2. **냉장고 관리**에서 식재료·수량·단위·소비기한·보관 방식 입력 (자주 쓰는 재료 버튼으로 빠르게 추가)
3. **메뉴 추천** → 추천 카드에서 **상세 조리법 보기**
4. 요리 후 **다 쓴 재료 정리하기**로 냉장고에서 빼기

처음 체험할 때는 빈 냉장고 화면의 **예시 식재료로 체험하기** 버튼을 눌러 보세요. (예시임이 화면에 표시되며 언제든 삭제 가능)

---

## 2. GitHub에 올리기 (터미널 없이, 웹사이트에서)

1. https://github.com 에 로그인 → 오른쪽 위 **+** → **New repository**
2. Repository name: `fridge-meal` → **Public** 또는 Private 선택 → **Create repository**
3. 생성된 페이지에서 **uploading an existing file** 링크 클릭
4. 압축을 푼 `fridge-meal` 폴더 **안의 내용물 전체**를 끌어다 놓기
   - `package.json`, `index.html`, `src` 폴더, `api` 폴더, `public` 폴더, `vercel.json` 등이 **맨 위에** 보여야 합니다.
   - `node_modules`, `dist` 폴더는 올리지 않아도 됩니다(압축 파일에 포함되어 있지 않음).
   - 숨김 파일(`.gitignore`, `.env.example`)이 안 보이면 올리지 않아도 동작에는 문제없습니다.
5. 아래 **Commit changes** 클릭

> 팁: 폴더째 끌어다 놓았는데 `fridge-meal/package.json`처럼 한 단계 안쪽에 들어갔다면, Vercel 설정의 **Root Directory**를 `fridge-meal`로 지정하면 됩니다.

## 3. Vercel로 배포하기

1. https://vercel.com 에서 **Continue with GitHub**로 가입/로그인
2. **Add New… → Project** → 방금 만든 `fridge-meal` 저장소 옆 **Import**
3. Framework Preset이 **Vite**로 자동 선택되는지 확인 (Build Command `npm run build`, Output Directory `dist` — 기본값 그대로)
4. (선택) AI를 바로 쓰려면 **Environment Variables**에 아래 4번의 값을 입력
5. **Deploy** 클릭 → 1~2분 후 생성된 주소 접속

이후 GitHub 저장소의 파일을 수정하면 Vercel이 자동으로 다시 배포합니다.

## 4. 환경변수 목록

| 이름 | 필수 | 설명 |
|---|---|---|
| `ANTHROPIC_API_KEY` | AI 모드에만 필요 | Claude API 키. 없으면 데모 모드로 동작 |
| `ANTHROPIC_MODEL` | 선택 | 사용할 모델. 비워 두면 `claude-sonnet-5-5` |

브라우저 코드에는 키가 들어가지 않습니다. 키는 Vercel 서버 함수(`api/recommend.ts`)에서만 읽습니다.
**API 키를 GitHub 파일에 직접 적지 마세요.**

## 5. AI API 연결 방법

1. https://console.anthropic.com 에 가입 → 결제 수단/크레딧 등록 → **API Keys**에서 키 생성 (`sk-ant-...`)
2. Vercel 프로젝트 → **Settings → Environment Variables**
   - Key: `ANTHROPIC_API_KEY`, Value: 생성한 키 → **Save**
3. **Deployments** 탭 → 최신 배포의 `⋯` → **Redeploy** (환경변수는 다시 배포해야 적용됨)
4. 사이트 오른쪽 위 배지가 **AI 추천 모드**로 바뀌면 연결 완료

AI 모드에서는 추천 1회에 20~40초 정도 걸릴 수 있고, API 사용량만큼 비용이 발생합니다.
AI 응답이 실패하거나 조건을 어기면 자동으로 데모 추천으로 대체되고 화면에 그 사실이 표시됩니다.

---

## 6. 데모 모드와 AI 모드

| | 데모 모드 | AI 추천 모드 |
|---|---|---|
| 표시 | 노란색 **데모 모드** 배지 | 초록색 **AI 추천 모드** 배지 |
| 메뉴 후보 | 내장 메뉴 데이터 37개 (`src/lib/recipes.ts`) | AI가 새로 제안 |
| 추천 이유 | 규칙으로 자동 작성 | AI가 작성 |
| 조리법 | 미리 작성된 구체적 조리법 | AI가 작성 (시간·불 세기·분량 포함하도록 지시) |
| 우선 소비 재료 계산 | 날짜 규칙 | 날짜 규칙 (AI에게 결과 전달) |
| 필수 조건 검증 | 규칙 | AI 응답을 **브라우저에서 규칙으로 재검증** |

데모 모드도 입력한 재료·소비기한·설정을 실제로 계산하므로, 재료나 조건을 바꾸면 결과가 달라집니다.
AI가 연결된 상태에서도 **사용자 설정 → 추천 모드 → 데모 모드로 추천받기**를 켜면 데모 모드로 바꿀 수 있습니다.

## 7. 추천 로직

`src/lib/recommend.ts`

1. **소비기한 분류(날짜 규칙)** — 지남 / 오늘까지(D-day) / 1~3일 / 4~7일 / 여유
2. **기한 지난 재료 제외** — 보유 재료로 취급하지 않음 (그 재료가 필요하면 '구매 필요'로 계산)
3. **필수 조건 필터** (순서대로)
   - 알레르기·금기 재료 (예: `우유` → 치즈·버터 포함, `밀` → 간장·고추장 포함까지 넓게 제외)
   - 조리도구 / 최대 조리시간 / 요리 실력보다 어려운 난이도
   - 보유 주재료 0개인 메뉴
   - 추가 구매 개수 (구매 불가 = 0개, 가능 = 최대 3개, **기본 양념 포함**, 보유 양념은 제외)
4. **점수화** — 오늘까지 재료 +40, 1~3일 재료 +18, 4~7일 +4, 보유 비율, 구매 1개당 −9, 선호 음식 +12, 선호 맛 +5, 매운맛 초과 감점, 비선호 −30
5. **선정** — 오늘까지인 재료를 쓰는 메뉴를 재료별로 먼저 확보 → 남은 자리를 점수순으로 채움 → 최대 3개 (조건을 만족하는 메뉴가 적으면 그만큼만)
6. 오늘까지인 재료를 쓰지 못하면 **구체적 사유 + 대안**(조건 변경, 냉동 보관, 상태 확인)을 표시

취향은 3단계를 통과한 메뉴 안에서만 순위에 반영되므로 필수 조건보다 우선하지 않습니다.

## 8. 데이터 저장 방식

브라우저 **localStorage**에 저장되어 새로고침해도 유지됩니다. 서버에는 저장하지 않습니다.

| 키 | 내용 |
|---|---|
| `fh.inventory.v1` | 식재료명·수량·단위·소비기한·보관 방식 |
| `fh.settings.v1` | 요리 실력, 선호/비선호 음식, 선호 맛, 맵기, 조리 가능 시간, 추가 구매 의향, 조리도구, 알레르기·금기 재료, 보유 양념, 모드 설정 |
| `fh.lastResult.v1` | 마지막 추천 결과 (새로고침해도 상세 조리법 확인 가능) |

- 같은 브라우저·같은 기기에서만 유지됩니다. (다른 기기, 시크릿 창에서는 비어 있음)
- 브라우저의 사이트 데이터를 삭제하면 함께 지워집니다.
- **사용자 설정 → 데이터 관리**에서 초기화할 수 있습니다.

> 여러 기기에서 같은 데이터를 쓰거나 사용자 테스트 결과를 모으려면, 다음 단계에서 Supabase 같은 DB를 붙이면 됩니다.

## 9. (선택) 내 컴퓨터에서 실행해 보기

배포만 할 거라면 필요 없습니다. 코드를 직접 고쳐 보고 싶을 때만 사용하세요.

```bash
# Node.js 18 이상 설치 후
npm install
npm run dev      # http://localhost:5173 (이 방식은 /api 가 없어 항상 데모 모드)
```

AI 모드까지 로컬에서 시험하려면 `npm i -g vercel` 후 `.env.local`에 키를 넣고 `vercel dev`로 실행합니다.

## 10. 폴더 구조

```
fridge-meal/
├─ api/
│  ├─ recommend.ts      # 서버: Claude API 호출 (API 키 보관)
│  └─ status.ts         # 서버: AI 연결 여부만 알려줌
├─ src/
│  ├─ lib/
│  │  ├─ expiry.ts      # 소비기한 날짜 계산 규칙
│  │  ├─ recipes.ts     # 데모 모드 메뉴 데이터 (37개, 조리법 포함)
│  │  ├─ recommend.ts   # 규칙 기반 추천 엔진
│  │  ├─ ai.ts          # AI 추천 요청 + 결과 재검증
│  │  ├─ match.ts       # 재료명·알레르기 매칭
│  │  └─ presets.ts     # 조리도구·양념·자주 쓰는 재료 등
│  ├─ pages/            # 홈, 냉장고 관리, 메뉴 추천, 상세 조리법, 설정, 온보딩
│  ├─ components/       # 공통 UI
│  └─ store.tsx         # 상태 관리 + localStorage 저장
├─ vercel.json
└─ package.json
```
